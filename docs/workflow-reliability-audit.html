What this page is

A design walkthrough using invented data. The repository's PowerShell check validates workflow structure only; it does not execute these records or contact external services.

A review path

A production review can trace one record from the trigger to the handoff, then add the guardrails the observed failure calls for.

01

Receive

Capture the raw webhook body before any transformation.

02

Validate

Reject missing identifiers and normalize the fields downstream needs.

03

Decide

Require structured output and keep an explicit fallback branch.

04

Route

Log status and failure context instead of silently dropping a record.

05

Approve

Create a draft or queue item; reserve live sends for a human.

Current demo boundaries

The demo uses environment-only LLM keys, validates contact fields and parsed output, records a review flag, and creates Gmail drafts instead of sending. Pre-call schema rejection, owner alerts, and dedicated exception logging remain follow-up work for a production scope.

What is intentionally absent?

No live credentials, customer records, production metrics, autonomous payments, bulk outreach, or automatic customer-facing sends.
